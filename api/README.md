# PriPriTrip API

FastAPI (async) on SQLite, with fastapi-users for accounts and Alembic for
the schema. In development it runs on `http://localhost:8000` (the port is
`API_PORT` in `api/.env`; a worktree has its own). In production nginx serves
it under `/api` (see [../deploy/README.md](../deploy/README.md)).

## Run it

From the repo root:

```bash
make setup      # once: .venv + pip install, and api/.env with a JWT_SECRET
make seed       # seed accounts + the sample trips (replants them on re-run)
make dev-api    # migrate, then uvicorn with --reload on API_PORT
```

`make dev-api` runs [dev.sh](dev.sh): it brings the database up to date
(`python -m app.migrate`) and starts uvicorn. By hand:

```bash
cd api && . .venv/bin/activate
python -m app.migrate
uvicorn app.main:app --reload --port 8000
```

- Health: `GET /health` → `{"status": "ok"}`
- Interactive API docs: http://localhost:8000/docs

## Settings

All in `api/.env` (made from [.env.example](.env.example) by `make setup`;
every setting is described there). In production they're Fly env vars
(`fly.toml`) or secrets.

| Setting | Required | What it does |
|---|---|---|
| `JWT_SECRET` | yes | Signs sign-in tokens. Generated by `make setup` |
| `DATABASE_URL` | | SQLite file (default `./data/app.db`) |
| `PHOTO_DIR`, `DOCUMENT_DIR` | | Where journal photos and trip documents are stored |
| `CORS_ORIGINS` | | The UI's origin(s), comma-separated. Never `*` |
| `API_PORT` | | The dev port (dev.sh) |
| `SEED_*_EMAIL` / `SEED_*_PASSWORD` | | The seed accounts (user, admin, viewer) |
| `GOOGLE_MAPS_API_KEY`, `GOOGLE_MAPS_MAP_ID` | | Handed to the browser by `GET /config` (maps, place search) |
| `OPENWEATHER_API_KEY` | | Server-side only: the Weather tool |
| `UMAMI_URL`, `UMAMI_WEBSITE_ID` | | Handed to the browser by `GET /config`: usage analytics |

## The database

- **Schema changes are Alembic migrations** in [migrations/versions/](migrations/versions/).
  After changing a model:
  ```bash
  cd api && . .venv/bin/activate
  alembic revision --autogenerate -m "what changed"   # then read and fix it
  make migrate                                          # from the root
  ```
  A test fails if the migrations and the models disagree, and `HEAD` in
  `tests/test_migrations.py` is bumped with each new one.
- `make reset-db` deletes the dev database (the one `DATABASE_URL` names),
  migrates a fresh one and re-seeds. Restart `make dev` afterwards: a running
  API keeps connections to the deleted file.
- **Seed** ([app/seed.py](app/seed.py)): creates the three accounts if
  missing and replants the sample trips (`app/sample_data/`), shared with the
  viewer. It deletes those trips' journals.

## Tests and lint

```bash
make test-api    # pytest (an in-memory database per test)

```

## Code layout

```
app/
  main.py            the app: routers, CORS, the password-change gate
  settings.py        settings from .env
  models.py          SQLAlchemy models (UUID ids, soft delete, owned by user_id)
  schemas.py         Pydantic request/response models (camelCase on the wire)
  trip_document.py   the trip document (import/export shape); schema/trip.schema.json is generated from it
  users.py           fastapi-users setup (sign-in, current_user, current_superuser)
  zones.py           time zone at a coordinate (computed on read, never stored)
  routers/           thin HTTP layer, one file per area
  services/          the logic: trips, sharing, memories, photos, documents, packing, weather, users…
  seed.py, migrate.py, make_admin.py, backfill_photos.py, schema_export.py   command-line helpers
migrations/          Alembic
tests/               pytest
```

Conventions (from [../AGENTS.md](../AGENTS.md)): async everywhere; every
row reached through an owned or shared trip, with 404 for anything else;
soft delete; admin routes under `/admin` behind `current_superuser`; thin
routers with the logic in `services/`.

## The API, by area

| Area | Routes |
|---|---|
| Accounts | `/auth/login`, `/auth/refresh`, `/auth/change-password`, `/users/me` |
| Trips | `/trips` (list), `/trips/import`, `/trips/{id}` (read, delete), `/trips/{id}/export`, and editing: `/trips/{id}/days/{date}`, `items`, `stays`, `travels`, `points-of-interest` |
| Sharing | `/trips/join`, `/trips/{id}/members`, `edit-code`, `view-code`, `membership` |
| Journal | `/trips/{id}/memories`, `…/memories/{id}/photos`, `/photos/{id}/{thumb\|display\|original}` |
| Tools | `/trips/{id}/weather`, `/trips/{id}/packing`, `/trips/{id}/documents` |
| Client | `/config` (Maps key, Umami), `/timezone?lat=&lng=` |
| Admin | `/admin/users` (list, invite, role, analytics, reset password), `/admin/backup/*` (the Pi) |
| Schema | `/schema/trip` |

## Command-line helpers

```bash
python -m app.make_admin someone@example.com   # make an account a superuser
python -m app.backfill_photos                  # make backfill-photos: place photos for old locations
python -m app.schema_export                    # make schema: regenerate schema/trip.schema.json
```

On Fly, run them with `fly ssh console -C "python -m app.…"`.
